# Configured request and evidence proposal

This proposal extends the tested W5 cleanup source with configured profiles and
metadata-only menus. It is local source for review. It does not select a serving
profile, change the running service, or grant a native execution allowance.

`PROPOSAL.json` pins the candidate modules, authoring tools and nine protected
helpers. `D2.patch` changes the physical controller relative to
`../evidence-capacity`. `SOURCE.patch` records the authoring-tool changes against
that stage. The retained proposal records and sealed A/B evidence are unchanged.

## Changes

- Build settings, the benchmark specification, resolved HTTP bindings and CLI
  arguments from the same authenticated run, host and menu.
- Admit bounded context, pool, prefill, memory-fraction, recurrent-slot and time
  reductions, the two declared instrumentation modes, per-row stop policy and
  explicit aliases of the frozen request corpus. All primary limits may only
  tighten the authenticated baseline ceilings.
- Store source references and metadata updates in client-binding schema 2.
  Prompt text and tokenizer vectors remain in the immutable nested corpus.
  Resolve aliases through a bounded cache; reject prompt or token-vector updates.
- Write three requests per schema-3 receipt file. Preserve each original byte
  field and digest, write-once ownership, atomic publication and existing byte
  ceilings. Retained per-request schema-1 and schema-2 receipts remain readable.
  Compress the complete canonical request-chunk envelope to avoid retaining the
  base64 transport overhead in every physical file. Bound both inflation layers.
- Use decode-log interval 100 in production and 1 when instrumented. The
  selected kernels, precision, caches, draft width and overlap setting remain
  fixed. This changes diagnostic cadence and still needs native validation.
- Join authenticated oracle rows through their frozen source ordinals. Cap work
  retains its wire evidence and receives no answer oracle or passing grade.
- Materialize CPU packets with the declared paired row count and authenticate
  that count in the common policy and release-binding proof. Retain the existing
  CPU resource and time ceilings; larger menus still need native timing proof.

## CPU verification

The public tests use only the standard library on the workstation. The separate
`tests/check_configuration_mutations_packet.py` command authenticates the sealed
donor and exercises its actual controller and producer/reader interfaces on
fresh copies. Its explicit substitutes cover external runtime, device and
process observations. It does not start a model or decode synthetic responses.

The private check retains a source patch for its producer-interface adaptation.
It tests the full menu, all-cap envelope and doubled menu through receipt
packing, export, receive, HTTP readout, owner acceptance, wire references and CPU
quality-input projection. The expected runtime-build proof remains required at
prelaunch. Its negative controls retain the original acceptance validators.

The diagnostic fixture allows 512 bytes per decode line on each of two ranks,
plus 4 MiB of startup and prefill messages. Non-bundle stdout has a separate
4 MiB startup envelope; the complete variable artifact line is measured. The
pinned runtime logger's complete
method is exercised to check its interval gate. This finite capacity envelope
does not establish a universal bound on runtime warnings or errors.

Use a fresh output file for each check. Failures remain in the private test
workspace. Current results and their limitations are recorded in
`../../CLEANUP-PROGRESS.json`.

## Remaining gates

The new protected diff needs exact owner review before native adoption. A fresh
packet also needs runtime-source preflight, exact one-use GPU approval, token-ID
comparison and native answer grading. The earlier A/B pilot predates this
proposal and does not qualify it.

The larger cleanup still includes the remaining shared-helper/import closure,
  stock runner and post-load hook, moving verify metadata preparation before
replay, and then shared-head and packed-view memory recovery. Native equality
and startup memory proofs remain required for those changes. Recovered memory
stays as headroom.

The owner corrected the handoff's repository constraint and approved publication
to [the existing public repository](https://github.com/Drgr33nSenior/Spry.ai-rdna4-serving).
Private run evidence remains outside Git.
