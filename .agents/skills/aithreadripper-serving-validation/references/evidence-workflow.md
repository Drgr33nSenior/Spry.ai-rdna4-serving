## Prepare and run

### Source-boundary preflight

Run `make test-validation-preflight PYTHON=/path/to/declared/python` before a
native run that changes a validator, producer or package boundary. This bounded
standard-library gate runs the actual public callable guard, package builder and
collector entry tests. Its frozen width corpus retains the failed width-eight
startup assumption and the corrected producer-to-reader path for widths four
and eight, both contexts and both ranks. Descriptor substitutes do not establish
GPU allocation, kernel correctness, model quality or native readiness.

For an actual worker with this startup interface, set
`SPRY_PREFLIGHT_WORKER_SOURCE` to its canonical source path and
`SPRY_PREFLIGHT_WORKER_SHA256` to its independently recorded pin. The same tests
then execute that worker's `_precision_weights` and `_full_enabled_indices`
bodies. A missing helper, changed call site or failed negative case must fail;
do not skip it. The retained reader still needs a separate check against the
packet's actual reader and contract. This optional input supplies no launch
authority.

Test the exact generated and consumed closure before spending another native
run: startup producer, reader, contract, package caller and collector. Exercise
every admitted arm width through the startup call site and reader. Derive
fixtures from retained raw failures and actual profiler SDK schemas. Do not
invent an interchange shape or test a replica of the validator. Check the
caller's output paths against the collector's actual path contract.

Compile complete consumed modules for callable identity. Preserve global
imports and future statements; compile body mutations from complete source
instead of assuming integers occupy `co_consts`. Run compiler-sensitive checks
with the packet's explicitly declared native Python. A Mac ARM Python 3.11 pass
does not establish a native x86 Python 3.14 pass. Do not borrow an executable
from an older baseline profile.

Reuse authenticated unchanged receipts. Review and rerun the changed source
closure and its affected boundaries; preserve failures. Keep one current
readiness and next-command pointer per experiment, with remaining gates and
the exact declared interpreter. Update it after a result instead of adding a
parallel launch or approval workflow.

### Native execution

Reuse the existing source-pinned builder, package checker, launcher preparer,
finite `local_commands.run` receipts and independent release observer. Keep the
eight protected owner/transport/resource/identity helpers unchanged. Observe
existing ownership and release; do not preempt another run or reserve resources
while waiting for a handover. Each launch nonce is single-use.

The owner writes `diagnostic.lock.unresolved.json` when it acquires the lease,
and removes it only after independent release. Its presence during an active
owned run does not by itself establish a failure. Keep later packets' read-only
absence prechecks queued until release; CPU preparation can continue. Preserve
any premature precheck refusal and repeat the unchanged check after release.
Do not clear the journal manually or bypass its refusal.

Receipt-producing checks, including read-only remote admission, still write local
files. Run them before sealing or from a fresh mutable native/reader root. Never
run them from a sealed author root. Seal only after its last receipt and review
record; later native checks must leave that author untouched.

Use native CPU tokenization and final decoding without GPU device mounts or model
weights. Do not import Torch, Triton or SGLang on the Mac. Use canonical temporary
paths for local CPU fixtures: `local_commands.run` binds `TMPDIR` to the private
root's `tmp`; default macOS aliases caused false fixture failures before.

Keep the current package ceilings: 64 archive members, 16 MiB archive, 32 MiB
combined transport, 256 argv entries and 64 KiB bindings. Recheck actual values
after edits; these packets run close to their limits. Preserve the current finite
owner, memory, swap, process and scratch bounds from the selected source. Do not
silently borrow limits from the deferred FP8-KV direction or expand them.

After successful native completion, use `collect_results.py` and the independent
`observe_closeout.py`, then seal the run before offline grading. On failure,
retain the failed campaign and use the existing failure-aware release procedure.
Do not retry the same nonce. Stop automatic retries after a failed bounded run;
inspect the retained failure before preparing any new campaign.

## Authenticate the readout

Reuse complete source, runtime, weight, worker identity, HTTP and release checks.
Join metadata-only startup BF16 cache witnesses to the authenticated workers on
both ranks. Retain graph/commit/speculative counters and every output difference.

The HTTP receipt's response SHA256 hashes the raw response bytes. The serving
contract's `raw_response_sha256` hashes canonical response JSON **plus a newline**.
Check both definitions correctly; confusing them caused a reader-only refusal.

## Lifecycle and sampling evidence

The [both-order lifecycle record](../../../../provenance/SPRINT7-LIFECYCLE-20261021.json)
indexes the thinking-enabled C2, reuse, branch, pressure, cancellation and
repeated-start screen. Use the current pointer for its sealed readers. The

native attention. Do not infer C2 coverage from a configured graph bucket or
a barrier alone. Require observed batch-two replays on both ranks and reconcile
each request's verifier count with singleton and batch-two group counts.

Native `origin_input_ids` can be `array('q')`. When joining a request to its
frozen input, validate bounded integer IDs and hash a canonical list together
with the separate cache salt. A list-only fixture missed this native type.

Test failure paths through their final retained output. If validation can throw
after deferred tensors have become host values, retain a bounded numerical
witness before those values are discarded. Include request, rank, width and
failed-predicate identities. Exercise the actual traceback or export reader;
partial host counters alone cannot explain a lost tensor-derived value. Failed
records remain ineligible for completion or quality acceptance. Do not add
device reads to the error path or relax the original predicate for logging.

Slot bookkeeping may read bounded integer allocator indices outside graphs;
report this instrumentation and avoid timing claims. Free plus cached slots
can account for the pool even when not every slot is free. These observations
do not establish numerical state equality or per-node cache ownership.

Keep one finite commit-observation limit derived from the packet's admitted
output caps plus the existing startup allowance. Bind the producer, snapshot
and integration readers to it. Checking only the reader bound missed a producer
that still refused after 4096 calls. Preserve unchanged resource/time ceilings.
Startup probe minimization must retain the complete dependency closure of the
unconditional FP32-head and BF16-cache witnesses, even when J01 capture is off.

For non-greedy DFlash checks, HIP's generic sampling-availability flag does not
by itself describe the selector route. The selected worker has a separate
selector sampling branch. Authenticate its source and observe successful native
selector-accept returns for every frozen external request on both ranks;
readiness traffic cannot satisfy coverage. A small task screen establishes
route execution and observed answer quality, not sampling-distribution equality.

## Multi-device capture and sealed source inspection

On the selected Torch 2.14 stack, `torch.cuda.graph` caches a process-wide default
capture stream. For a component process that switches cards, create an explicit
stream for the selected device, verify its device, and pass it to the graph
context. The first Sprint 9 component attempt passed card-zero checks and failed
on card-one capture with the cached card-zero stream. The corrected run passed
both cards. See the [Sprint 9 record](../../../../docs/SPRINT9-TARGET-GRAPH.md).

Use `python -B` or `PYTHONDONTWRITEBYTECODE=1` when importing helpers from sealed
folders, including preparation scripts. A helper import added one `.pyc` after
Sprint 9.1 authentication; all original file hashes matched, but the folder's
membership seal failed. Preserve such a folder and make a fresh, documented
recovery snapshot. Do not delete the extra file, reset timestamps or silently
relabel the old seal as valid. A recovery never authorizes nonce reuse.
