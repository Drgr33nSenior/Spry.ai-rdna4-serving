# Frozen Qwen3.8 experimental baseline

The current Qwen3.8-27B-FP8 serving profile is frozen as an experimental baseline. This records the selected sources and evidence; it does not install a runtime or change production defaults. The next phase is feasibility work for Qwen3.8-Flash-Next, followed by a baseline and then separately reviewed thread-inspired optimizations. Shape-specific patches are not automatically transferable to another model.

The selected profile uses Torch 2.14.0+git2e66fe81.rocm10.2.0, ROCm SDK 10.2.0.dev20261020+git535d2990, HIP 7.17.26416 and RCCL 2.32.3, FP8 target weights, BF16 target and draft attention KV, DFlash2 width 8, `chat_template_kwargs.enable_thinking=true` and `reasoning_effort=low`, split-KV metadata reuse, and FP32 recurrent state and head arithmetic. FP32 head arithmetic does not establish FP32 resident head weights. It uses the selected b101 GEMM with W4 and aligned ring-fold, 19 usable/20 physical recurrent slots per card, the speculative replay flag enabled and the original compact replay flag disabled. The [provenance record](../provenance/QWEN38-FROZEN-BASELINE-20261023.json) binds the selected source, recurrent profile and their rollback identities.

On the bounded Sprint 22 short-workload comparison, the selected profile measured 121.18–121.24 combined TP2 output tokens/s at C1, with 2,047 input tokens and 1,024 forced output tokens. The matched-capacity Sprint 19 comparison saved 1.62558 GiB per card in startup allocation after graph setup. The Sprint 22 quality screens recorded 68 normal final answers, two cancellations, actual C2, slot accounting and independent release. These are finite workload observations, not whole-device or lifetime memory peaks, and they do not establish a general performance guarantee. See [Sprint 22](SPRINT22-GDN-OUTPUT-M16.md) and [Sprint 19](SPRINT19-MATCHED-RINGFOLD.md).

The [64K screen](SPRINT33-LONG-CONTEXT64.md) completed 14 normal-stop responses with 59,999-token long inputs and 567–849 output tokens. Its literal and factual gates both failed at 10/12 because two responses used a string for an action-order array; those failures are not covered by the Sprint 32 owner exception. The optional 64K guard patch is not a global default. The screen did not exercise the full output allowance or establish general 64K quality.

The earlier numerical variation and cause remain unresolved. Sprint 11's failed matched-work gates remain recorded. Sprint 32's strict 2/12 result and owner-accepted lexical exceptions remain distinct from Sprint 33. Endurance has not been run, and no general numerical equivalence, sampling-distribution equivalence or production qualification is claimed. Rollback remains available as recorded in the provenance.
