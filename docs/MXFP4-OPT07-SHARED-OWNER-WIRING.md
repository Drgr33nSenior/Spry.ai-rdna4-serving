## What changed

The existing worker entrypoint wraps the actual native scheduler target before
construction. It binds the target module, scheduler class, constructor, both
decorators and the first scheduler instance. Source descriptors use paths inside
the worker sandbox. Each rank receives its fixed menu, start identity, output
directory and optional profiler through this explicit entrypoint.

Both starts use the pinned profiling-twin Torch binary, rocprofiler tool-library
environment and raw mounts. That binary differs from the selected serving Torch.
Start 1 records CPU metadata without starting a capture. Start 2 records the same
metadata and seven fixed windows per rank: one long-C1 cold prefill window and six
decode windows. Both starts use the same C4 kernel and model configuration, including the
explicit cap-3 Mamba experiment. Cap-3 remains a proposed runtime deviation, not a
global selection change. The existing environment record is reused. Live hooks
on all 48 GDN layers are deferred; this packet cannot establish F1 engagement.

The device receipt now has a production writer. At the first native callback it
joins the existing PCI/UUID validator with the current Torch device and publishes
the rank receipt. Tests use synthetic devices; the physical join is unmeasured.

## Publication and retention

The trust root is the parent barrier after HTTP validation and before teardown.
The parent hashes the completed worker close receipt there. The worker's core and
capture digests are nested inside it; the worker does not transmit its own outer
close-pin object. The barrier has a five-second limit inside the owner deadline.
Before the barrier, the parent reads each full native worker record and joins it
to the compact readiness gate by rank, process identity, source binding and digest.

Collection rejects unlisted members, links, nonregular files, changed reads and
oversized data. Successful replay requires the exact expected files. Failed
starts retain bounded raw records, including absent, partial or single-rank
publication, through the existing failure-aware caller. A successful collection
permits the appropriate closeout observer. If collection fails, neither closeout
observer runs; release remains unverified and must be established before another
operation. Failure records cannot become a successful readout or quality input.

The generated frame protocol reserves **334.5 MiB** within the existing 512 MiB
session limit. It replaces the larger generic log reservations with 16 MiB per
stdout/stderr stream and limits each diagnostic tree to 15 MiB. Two dedicated
32 MiB raw trace mounts are charged against the existing scratch reservation.
Compressed prefill and decode files retain their 768 KiB and 320 KiB limits.
Power, privilege, owner deadlines and the session and scratch ceilings remain
unchanged. The package's fixed vocabulary expands to 89 archive members; that
transport change must be included in the exact owner decision.
